# tools/data — 오프라인 정차 후보 데이터 (휴게소·졸음쉼터·화장실·주유소·주차장)

앱(`app/src/main/assets/data/`)에 넣는 JSON을 만드는 스크립트다. 공공데이터와 OpenStreetMap을
내려받아(`fetch.py`) 정제·지오코딩·교차검증한 뒤 내보낸다(`build.py`). API 키나 회원가입은 쓰지 않는다.
다운로드 기준일: **2026-11-11** (OSM Overpass 스냅샷 2026-11-11T00:09~00:14Z).

## 실행

```bash
RAW=/path/outside/repo/data-raw          # 원본 보관 위치 (저장소 밖, 약 1.2 GB)
python3 -I -B tools/data/fetch.py "$RAW"                 # 다운로드 (이미 있는 파일은 건너뜀, --force로 갱신)
python3 -I -B tools/data/build.py "$RAW" app/src/main/assets/data   # 첫 빌드 약 5분(이후 캐시로 30초), 리포트 $RAW/build_report.json
python3 -I -B tools/data/validate.py app/src/main/assets/data       # 형식·좌표·id·영업시간·차로 방위·고속도로 선형 검사
./gradlew -p rest-engine buildStopTable                            # 앱이 읽는 stops.bin (StopTableTest가 JSON과 비교)
```

테스트 자료(원본이 바뀌었을 때만 다시 만든다, 고정 시드):

```bash
python3 -I -B tools/data/road_samples.py "$RAW" rest-engine/src/test/resources/stops/road_samples.csv          # 지도 맞춤 표본
python3 -I -B tools/data/replay_positions.py "$RAW" rest-engine/coach/src/test/resources/stops/replay_positions.csv  # 실제 차로 위 위치
```

- 표준 라이브러리만 쓴다 (Python 3.9+). `-I`(격리 모드)로 실행하므로 스크립트가 자기 폴더를 `sys.path`에
  넣는다. `-B`는 저장소에 `__pycache__`를 남기지 않기 위한 것이다.
- 내려받은 파일은 신뢰하지 않는 입력으로 다룬다(파싱만 하고 실행하지 않음). 원본은 저장소 밖에 둔다.
- `fetch.py`는 모든 다운로드를 `$RAW/manifest.json`에 기록한다(URL, 시각, 바이트, sha256, 행 수).
- 정부 포털(file.localdata.go.kr, data.go.kr)은 브라우저가 아닌 요청을 WAF에서 403으로 막는다. 그래서
  일반 데스크톱 브라우저 User-Agent와 Accept 헤더를 보낸다(포털의 다운로드 버튼과 같은 요청).
  개인정보나 프로젝트 식별자는 보내지 않는다. Overpass에는 일반 클라이언트 이름만 보낸다.

## 출력 파일 (`app/src/main/assets/data/`)

**앱이 실제로 읽는 것은 `stops.bin`이다.** JSON을 다시 만들었으면 `./gradlew -p rest-engine buildStopTable`로
`stops.bin`(형식 2: 정차 후보 60,084행의 열 단위 이진 표 + 고속도로 선형, 5.05 MB)을 다시 만든다. 변환 규칙은
`rest-engine/src/main/kotlin/dev/shimpyo/engine/stops/StopRows.kt` 하나이고, `StopTableTest`가 JSON 전 행과
`stops.bin`을 비교한다(둘이 어긋나면 실패). JSON 파일은 공개 데이터 원본으로 저장소에 두되 APK에는 넣지 않는다
(`app/build.gradle.kts`의 `ignoreAssetsPattern`). 예전처럼 앱이 JSON을 직접 읽으면 에뮬레이터에서 18초 동안 GC가 돌았다.


모든 파일은 UTF-8, 공백 없는 JSON 배열이다. 숫자는 숫자로 쓴다. **키가 없으면 값이 없거나 모르는 것이다.**
불리언은 `1`/`0`이고, 원천이 Y/N을 항상 채우는 필드(화장실의 `dp`·`bell`·`cctv`·`dis`)는 `1`일 때만 쓴다
(행정안전부 행은 없으면 N, OSM 행은 없으면 모름). 좌표는 WGS84. `id`는 같은 원천 레코드에서 다시 만들면 같은 값이 나오는 짧은 해시다.

앱 모델(`rest-engine`의 `StopCandidate`)과의 대응: `rest_areas` → `HIGHWAY_REST_AREA`, `drowsy_shelters` →
`DROWSY_SHELTER`, `restrooms` → `PUBLIC_RESTROOM`(`parkable = pk==1`), `parkables`의 `fuel`/`lpg`/`h2` →
`GAS_STATION`, `park` → `PUBLIC_PARKING`(`walkDistanceM = wcd`). 시설 플래그는 `wc`/`dp`/`nr`/`bell`/`cctv`/
`dis`/`food`/`gas`/`ev`/`h24`가 `Facilities`의 같은 이름 항목에 해당한다.

| 키 | 형 | 내용 |
|---|---|---|
| `id` | str | `k…` 한국도로공사 표준데이터, `o…` OSM(민자고속도로) |
| `n` | str | 이름 (예: `안성휴게소`) |
| `rt` | str | 노선명 원문 (한국도로공사: `경부선`, OSM: 고속도로명) |
| `hw` | str | 그 지점 OSM 고속도로명 (예: `경부고속도로`) |

| `dir` | str | 정규화한 방향: `<목적지>방향` 또는 `양방향` (예: `부산방향`) |
| `dirRaw` | str | 원문 방향: 한국도로공사 `상행`/`하행`/`양방향`, OSM은 이름 원문 |
| `hdg` | int | 이 휴게소로 들어가는 차로의 진행 방위(도, 북 0 시계방향). 양방향 휴게소는 없음 |
| `lat`,`lon` | num | 위치 |
| `k` | str | `general` 일반 / `truck` 화물차 / `simple` 간이휴게소 |
| `wc` | int | 화장실 (항상 1) |
| `nr` `ev` `gas` `lpg` `ph` `food` `shop` | int | 수유실, 전기차충전, 주유소, LPG, 약국, 음식점, 매점 |

| `park` | int | 주차면수 |
| `op`,`pv` | str,int | 운영사(민자는 OSM 고속도로 operator), 민자고속도로면 `pv=1` |
| `src` | str | `kec` / `osm` |
| `osm`,`xm` | str,int | 짝지은 OSM 요소(`w123`…)와 한국도로공사 좌표와의 거리(m) |
| `pos` | str | `osm`: 원천 좌표가 반대편 차로 옆이라 OSM 위치로 바꿈 / `shared`: 원천에서 두 방향이 같은 좌표 |

### drowsy_shelters.json — 졸음쉼터

`id`(`d…` 한국도로공사, `o…` OSM), `n`, `rt`, `hw`, `rno`, `dir`, `dirRaw`(원문 `서울기점 + 부산종점`),
`hdg`, `km`(설치현황의 이정, km), `lat`, `lon`, `k`(`drowsy`), `wc`(화장실 1/0, OSM은 모르면 없음),
`park`(주차면수), `cctv`(대수), `etc`(기타편의시설), `a`(주소), `op`, `pv`, `src`, `osm`, `xm`, `pos` — 뜻은 휴게소와 같다.

| `dis` | int | (주차장) 장애인전용주차구역 보유 |
| `wcd` | int | (주차장) 가장 가까운 화장실까지 거리(m, 300 m 이내일 때) |

### motorways.json — 고속도로 차로 선형 (지도 맞춤용)

`r`(OSM 고속도로명, 휴게소·졸음쉼터의 `hw`와 같은 이름), `ow`(1 = 일방통행이고 점 순서가 진행 방향, 0 = 양방향 통행),
`p`(`[lat, lon, lat, lon, …]`, 소수 5자리). 이름 없는 way 89개는 뺐다. 앱은 이것으로 내비 없이 "지금 어느 고속도로를
달리는지" 맞춰 같은 길의 휴게소를 먼저 고른다(`rest-engine` `MotorwayIndex`, 흔들린 표본 1,500곳에서 맞음 99.9%).
OSM 파생 데이터라 ODbL이다(아래 출처 문구의 "고속도로 선형").

### meta.json

`schema`(2: `motorways.json` 추가), `built`, `downloaded`, 파일별 `counts`, 앱에 표시할 `attribution` 문구.

### 앱의 해석 (`rest-engine` `StopRows`·`StopHours`)

- 영업 시간 `HH:MM-HH:MM`: 여는 시각 = 닫는 시각이면 24시간(경찰서·소방서·주유소 화장실의 교대 시각), 닫는 시각이 24시를
  넘으면 다음 날(`05:00-24:20`), `23:59`는 그날 끝. 주차장은 `days`에 없는 날 휴무, 있는 날은 `oh`(평일)·`ohs`(토)·`ohh`(일요일·공휴일).
  공휴일은 양력 고정 공휴일과 대체공휴일, 2026년 음력 명절·선거일. 시각대 Asia/Seoul.
- 휴게소·졸음쉼터의 `hw`는 `stops.bin`의 고속도로 색인이 된다(같은 길 순위).

## 처리 방법

### 공중화장실 좌표 (키 없는 오프라인 지오코딩)

행정안전부 공중화장실 데이터는 **2025년 2월부터 좌표가 빠졌다.** Open API만이 아니라 표준데이터 파일도
마찬가지다: data.go.kr 15012892/15075531 페이지에 "원천데이터 정책 변경에 따라 … 좌표정보가 제외되어
(2025년 2월) … [제외 항목] WGS84 위도, WGS84 경도"라고 적혀 있고, 실제 CSV(34열)에도 좌표 열이 없다.

같은 LOCALDATA 시스템의 다른 데이터는 아직 좌표를 준다. 그래서 주소 → 좌표 사전(gazetteer)을 만든다.

1. 참조점: 안전비상벨·CCTV·무료와이파이·민방위대피시설(WGS84), 석유판매업·약국·휴게음식점·일반음식점
   인허가(EPSG:5174), 전국주차장정보(WGS84). 좌표가 있는 약 345만 점.
   - 인허가 좌표계는 EPSG:5174(Bessel, 중부원점 127°00'10.405", 7-파라미터)로 판정했다. 같은 주소의 WGS84
     참조점과 비교해 중앙값 38 m (EPSG:2097로 보면 261 m). 변환은 `common.py`에 직접 구현(pyproj 없음).
     UTM-K 역변환은 민방위대피시설의 WGS84와 대조해 오차 0.00002 m.
2. 주소 파싱(`common.parse_address`): 도로명(시도·시군구·도로명·건물번호·지하) / 지번(읍면동리·산·본번·부번).
   띄어쓰기 없는 주소, `지봉로 13길` 같은 분리, 시도 약칭·옛 이름(강원도/전라북도, 광주광역시·전라남도 →
   전남광주통합특별시, 인천 중구·동구·서구 → 영종구·제물포구·서해구·검단구, 군위군 → 대구)을 처리하고,
   시도·시군구가 빠진 주소는 레코드의 `개방자치단체코드`로 채운다.
3. 키마다 참조점을 묶는다: 150 m 안에서 서로 맞는 점들이 과반이면 그 중앙값, 아니면 버린다.
4. 화장실마다 가능한 후보 중 추정 오차가 가장 작은 것을 쓴다(`ga`).
   - `r` 도로명 주소 일치 (참조점 1개면 60 m, 여럿이면 군집 반경)
   - `rm` 같은 건물 본번 (+20 m)
   - `ri` 같은 도로의 앞뒤 번호 사이 보간. 도로명 건물번호는 도로 시작점에서의 거리(약 10 m/번호, 홀짝은
     좌우)로 매겨져 보간이 잘 맞는다. 교차검증 중앙값 10 m(같은 쪽 번호 사이), p90 42 m.
   - `l` 지번 일치 (참조점 1개면 150 m)
   - `b` 이름과 도로/동이 같은 화장실 설치 비상벨
5. 시군구 중심에서 99백분위 반경의 1.3배(최소 8 km)보다 멀면 버린다(31건).
6. 같은 이름·주소의 레코드는 합친다(`cnt`). `미개방`은 뺀다.
7. OSM `amenity=toilets` 가운데 80 m 안에 행정안전부 화장실이 없는 것을 더한다(접근 private/customers 제외).

검증: OSM의 이름 있는 화장실과 이름이 같은 지오코딩 결과의 거리 중앙값 42 m, p75 86 m (241쌍).

### 휴게소·졸음쉼터 방향

- 한국도로공사 표준데이터가 기준이다. 휴게소 방향은 이름의 괄호(`안성(부산)` → `부산방향`), 졸음쉼터는
  `서울기점 + 부산종점` → `부산방향`. 괄호가 없고 원문이 `양방향`/빈값이면 `양방향`.
- `hdg`: OSM 고속도로는 방향별 일방통행 차로로 그려져 있다. 우측통행이므로 휴게소는 자기 차로의 오른쪽에
  있다. 방향 라벨은 **차로가 실제로 어디로 가는지**로 차로를 고른다: 시설 옆 두 차로를 OSM 차로 사슬(공유 노드, 진입로가
  본선 중간에 합류하는 것 포함)을 따라 30 km 가 보고 목적지에 더 가까워지는 쪽(직선거리 감소 / 주행거리)이 라벨의 차로다.
  쌍의 다른 방향 라벨이나 졸음쉼터의 'X기점'이 있으면 `목적지 쪽 − 기점 쪽`으로 판단한다(목적지가 15 km 안이라 못 쓰는
  라벨은 기점에서 멀어지는 차로). 점수 차가 0.3(라벨 둘이면 0.6) 미만이거나 사슬이 짧으면(긴 쪽 3 km, 짧은 쪽 0.5 km 미만)
  결정하지 않고 위치상 오른쪽 차로를 쓴다. 값은 그 차로 ±150 m 구간의 방위다.
  예전에는 그 자리 차로 방위와 목적지 직선 방위가 60° 안이면 결정했는데, 길이 돌아가는 곳에서 틀렸다(2026-11-11 감사:
  경부선은 대신졸음쉼터에서 2 km 동안 북북동으로, 호남선은 동광주에서 서남서로 달린다).
- `validate.py`는 같은 길(`hw`)·같은 방향(`dir`) 1~25 km 이웃들의 방위(1/d 가중 원형 평균)와 90° 넘게 다른 행, 같은 이름
  두 방향이 500 m 안인데 120°(3 km 안이면 90°) 미만으로 갈린 행을 문제로 센다(예전 데이터 8건 → 0건).
- 앱에서 "진행 방향 앞쪽"은 `hdg`와 차량 진행 방위 차이(예: 60° 이내) + 위치가 앞쪽인지로 판단할 수 있다.
- 민자고속도로: 한국도로공사 데이터에는 없다. OSM `highway=services`(이름에 휴게소)와 `rest_area` 중
  운영사가 한국도로공사가 아닌 고속도로 350 m(졸음쉼터 300 m) 안의 것만 넣는다. 2011년 이전 대량 입력된
  OSM 노드(id < 10억)는 오래된 자료가 많아 뺀다. 한국도로공사 노선의 OSM 추가 요소는 중복·폐쇄로 보고 쓰지 않는다.

### 주유소·주차장

- 주유소: 석유판매업 인허가에서 `업태=주유소`, `영업/정상`만. OSM 주유소는 150 m 안 등록 주유소와 합쳐
  브랜드·LPG·24시간을 더한다. 등록부에 없는 OSM 주유소는, 100 m 안에 폐업 주유소만 있으면 폐업으로 보고
  빼고(그 외는 `src=osm`으로 유지), LPG충전소(등록 체계가 달라 등록부에 없음)는 `k=lpg`로 넣는다.
- 주차장: 전국주차장정보표준데이터. 좌표가 없으면 위 지오코더로 추정(`gm`). 같은 이름이 30 m 안에 또
  있으면 하나만 둔다. 특기사항이 정기권·거주자 전용 등이면 `pk=0`.

  중앙값 58 m, 최대 1.2 km(적금·성남·일광).
- 지천졸음쉼터(경부선): 표준데이터는 부산방향, 설치현황과 위치는 서울방향 → 서울방향으로 고쳤다.
- 대덕졸음쉼터(호남선): 표준데이터 천안방향, 설치현황 순천방향. 이곳 호남선은 서남서(광주)로 가다 북쪽으로
  꺾이므로 위치(242°, 천안 쪽)가 표준데이터를 지지해 그대로 두었다.
- 광양·서천·완주·송탄·금성·창원 졸음쉼터: 한 방향의 좌표가 반대편 차로 옆이거나 두 방향이 같은 좌표라
  방위가 같게 나와, 두 라벨을 함께 보고 반대 차로를 배정했다.
- 대신졸음쉼터(경부선): 예전 빌드가 두 방향을 뒤바꿨다(부산방향 209°, 서울방향 31° — 이곳 경부선은 부산 쪽으로 가며 북북동으로
  달린다). 차로 사슬 판단으로 부산방향 30°·서울방향 211°이고, 위치도 한국도로공사 좌표와 같은 OSM 노드(이름의 방향이 맞는 것)다.
- 동광주졸음쉼터(호남선 천안방향): 61° → 242°. 순천졸음쉼터(남해선, 표준데이터·설치현황 모두 순천방향): 좌표가 부산방향
  차로 옆이지만 라벨을 따라 329°, 위치는 순천방향 차로 옆 OSM 노드로 바꿨다.
- 칠곡졸음쉼터(대구외곽순환선, 달서/동대구): 예전에는 두 목적지가 같은 쪽이라 비웠는데, 차로를 따라가 보면 갈려서
  달서 242°·동대구 63°. 유성졸음쉼터(호남지선, 좌표가 두 차로 사이): 라벨로 21°.
- 설치현황의 노선명을 바뀐 이름·구간 표기와 맞춘다(`서울외곽선` = `수도권제1순환선`, `남해선` = `남해선(순천부산)`,
  `청주영덕선` = `당진영덕선(청주영덕)` 등). 이정이 있는 졸음쉼터 209 → 247곳. 구리남양주졸음쉼터는 표준데이터만 일산방향이고
  설치현황·좌표·OSM 이름이 모두 판교방향이라 판교방향으로 고쳤다(설치현황과 위치가 맞으면 따르는 규칙).
- 표준데이터 방향 원문 오타: `양앙`(양양), `양기점`(양평기점), `광주광역시`/`광주` 혼용.


## 알려진 한계

- **화장실 위치는 추정값이다.** 같은 주소(건물·필지)의 다른 시설 좌표에서 가져오므로 건물 입구 기준이고, 큰
  공원·캠퍼스 안의 화장실은 수백 m 틀릴 수 있다(`ga`가 참고값). 원천 주소가 틀리면 위치도 틀린다.
- 개방시간은 자유 입력이라 `oh`는 첫 시간대만 담는다. 요일·계절별 시간은 `ohr` 원문을 보여 줄 것.
  4,111곳은 개방 여부를 모른다.
- 행정안전부 데이터는 지자체 입력이라 기준일이 제각각이다(2018~2026, 2024년이 가장 많음).
- 휴게소: 한국도로공사 데이터는 도공 운영 노선만 있다. 민자고속도로 29곳(OSM)은 수유실·전기차·음식점 정보가
  없고(주유소는 350 m 안 같은 방향 주유소로 추정, 28곳 `gas=1`), 일부는 방향 라벨이 없어 `hdg`만 있다. 국도 휴게소·국도 졸음쉼터는
  키 없이 받을 수 있는 공식 데이터가 없어 넣지 않았다(OSM 국도 휴게소는 대부분 2009년 일괄 입력 자료).
- `hdg`가 없는 곳: 양방향 휴게소 14곳(졸음쉼터는 없음). 민자 휴게소 29곳 중 15곳은 방향 라벨(`dir`)이 없고 `hdg`만 있다.
- 주유소: 등록부 영업 상태는 지자체 갱신 시점에 따른다. OSM 전용 1,294곳은 등록부로 확인하지 못한 것이다.
  주유소 화장실은 대부분 있지만 데이터 근거가 있는 곳만 `wc=1`이다.
- 주차장: 운영시간·요금은 지자체가 등록한 값이고, `pk=0`은 특기사항 문구로만 판단했다.
- `restrooms_nocoord.json`은 엔진에서 바로 쓸 수 없다(좌표 없음). 런타임 지오코더가 있을 때만 의미가 있다.

## 막힌 것 / 쓰지 않은 것

- **행정안전부 공중화장실 좌표**: 2025년 2월 원천에서 제외돼 Open API와 표준데이터 파일 모두 없음(위 참고).
- **data.ex.co.kr**(고속도로 공공데이터포털): 이 서버에서 접속 시간 초과. 같은 한국도로공사 표준데이터를
  data.go.kr에서 받았으므로 영향 없음.
- **data.go.kr Open API**(한국도로공사 휴게소 기준정보·편의시설, 행정안전부 생활안전지도 졸음쉼터 등): 서비스
  키가 필요해 쓰지 않음.
- **주소정보누리집 위치정보요약DB·내비게이션용DB**(건물 좌표): "제공하는 주소"라 신청과 본인인증이 필요해 쓰지
  않음. 같은 사이트의 공개 주소DB(건물DB 등)에는 좌표가 없다.
- **Nominatim 등 공개 지오코더**: 대량 지오코딩이 이용정책에 어긋나 쓰지 않음.
- file.localdata.go.kr은 기본 curl 헤더면 403을 준다(브라우저 헤더로 해결, 위 "실행" 참고). data.go.kr 파일데이터는
  포털이 CAPTCHA를 요구하면 `fetch.py`가 멈추고 수동 다운로드를 안내한다(이번에는 요구하지 않음).

|---|---|
| `fetch.py` | 다운로드 (data.go.kr 표준·파일데이터, LOCALDATA, Overpass) + `manifest.json` |

| `geocode.py` | 주소 → 좌표 사전(참조점 군집), `$RAW/gazetteer_cache.json` 캐시(입력 해시가 같으면 재사용, 빌드 30초) |
| `restrooms.py` | 화장실 정제·지오코딩·병합, 개방시간 파싱, OSM 화장실 추가 |
