현재 감사에서 확인한 High/Medium은 모두 수정했다. 수락 이유는 **결정 당시의 근거**를 보존한다. 휴식만 수락한 카드도 휴식 아이콘을 유지한다. 현재 거리/ETA는 기존 엔진의 실시간 후보 갱신을 계속 사용한다. 새 정차 선택/여정 초기화의 기존 해제 규칙은 유지한다.

### 수락 후 정확한 표시 예

- 질문: `화장실·충전 마지막 기회` / `충전 때 11km 남음`, `정체 1시간`.
- 내비 대기: `화장실·충전 · 내비에 넣는 중…` / 같은 이유 칩.
- 수락: `화장실·충전 · 들르기로 한 곳` / 같은 이유 칩.
- 경유지 성공: `화장실·충전 · 경유지로 넣었어요` / 같은 이유 칩.
- 경로 위 직접 진입: `화장실·충전 · 진입로로 들어가세요`. 중복 ‘경로 위’를 맥락 줄에서 빼고 지시문을 남긴다. 경로 위치는 거리 줄에도 표시된다.
- 충전 대신 주유도 같은 규칙. 이유가 없어도 휴식·충전 같은 목적은 남는다. 다른 장소의 추천/내비 결과는 섞지 않는다.

## 유지한 동작과 배치/대비 점검

- **한 번에 한 결정**: `DriveScreen.kt:185`의 들르기/괜찮아요 한 쌍과 고정 급해 버튼. 마이크 포함 최대 4개 목표(`theme/Dimens.kt:219`). 주행 중 계획·탑승자 버튼은 사라지며 그 자리는 유지된다. 급해는 최대 두 후보와 닫기, 마이크이고 주행 중 별도 뒤로 버튼은 없다(`urgent/UrgentScreen.kt:111`).
- **상태 전환**: 서비스 종료 카드는 오래된 추천을 숨긴다. 질문은 promptReasons를 사용한다. ActionRow는 질문 키 변경 후 600ms 동안 입력을 받지 않아 이전 버튼을 누르다 새 결정을 수락하는 것을 막는다(`DriveScreen.kt:179`). 진행 중에는 재시도 버튼 대신 정적인 내비 대기를 보여준다. `ShimpyoContent.kt:119`는 제한 상태면 해당 프레임부터 주행 화면을 선택하고 팝업을 닫는다. 급해 결과가 갱신되는 순간의 터치/CCP 동작은 아래 수동 항목으로 남긴다.
- **터치**: 주행 주요 버튼/마이크 100dp, 급해 120dp(compact 100), 주 행동 사이 24dp. 칩은 비조작 정보이므로 60dp 유지. `components/Buttons.kt:189`, `drive/DriveScreen.kt:185`, `theme/Dimens.kt:89`.
- **글자**: 이름/행동 40sp, 게이지 60sp(compact 48), 보조 28~30sp 유지. 이름 한 줄/문장 최대 세 줄, 자동 스크롤 없음(`theme/Type.kt:106`, `drive/DriveScreen.kt:244`). 긴 이름은 말줄임이므로 음성으로 전체 이름을 듣는지 확인한다.
- **840×1184 세로, 1.0배**: 좌우 40, 카드 안쪽 32 → 텍스트 폭 696dp. 12자 칩의 한글 전각 상한 약 360dp + 좌우 40dp, ‘정체 1시간’과 함께 한 줄 약 632dp로 들어간다. 실제 라틴 숫자는 더 좁다. 카드 높이 예산 약 376dp, 내부 312dp이며 맥락+이름104 / 거리46 / 두 칩 행156 = 306dp까지 들어간다. 이는 계산이며 렌더링 측정으로 확인한 것은 아니다.
- **1700×1184 가로**: 좌우 48, 두 단 사이 40, 오른쪽 비율 0.514 → 카드 약 804dp / 내부 약 740dp. 버튼 구성은 세로와 같다. 낮은 landscape/portrait는 compact 분기와 FitColumn으로 덜 중요한 행을 생략한다. 글자 확대에서 모든 문구를 동시에 보장하지는 않는다.
- **계산한 대비(라이트/다크)**: 카드 본문 18.42/16.67; 카드 보조(84%) 11.44/12.04; 칩 본문 15.89/12.80; 눌린 마이크/포커스 14.10/12.36; 눌린 급해 4.62/4.94. 코드의 실제 알파를 배경에 합성하여 sRGB 상대 휘도로 계산했다. 시스템 테마 추종은 유지(`theme/Theme.kt:44`).

## Low / 에뮬레이터 검증 필요

1. **실제 시선 시간**: 2초 내 목적·정차지·결정을 이해하는지는 코드로 통과 판정할 수 없다. 840×1184와 1700×1184, 라이트/다크에서 charge 질문 → 들르기 → 내비 성공을 녹화해 확인한다.
2. **폰트/말줄임**: 기본/큰 시스템 글자에서 긴 휴게소 이름, 화장실·휴식·충전 세 목적, 내비 진입로 지시, 두 이유 칩을 확인한다. Compact에서는 칩 다음 거리 줄이 생략될 수 있고, 이름·목적과 조작 버튼은 남아야 한다. 실제 큰 글꼴에서 문장형 INFO 카드까지 확인한다.
3. **보조 그래픽 대비**: 라이트 주황 게이지와 일부 경로 띠 색은 원래 4.5:1보다 낮다(`theme/Color.kt:389`, `components/Gauge.kt:44`). 현재 숫자·단계 배지·범례로 중복 전달하므로 이번에는 의미색을 바꾸지 않았다. 색만으로 읽지 않아도 되는지 야간/주간 화면에서 확인한다.
4. **터치/CCP**: 질문 갱신 직전/직후, 급해 결과 갱신 순간, 내비가 앞 화면으로 이동했다 복귀할 때 포커스와 실제 선택 대상을 확인한다. 소스 검토만으로 포인터 취소 시점을 검증하지 않았다.
5. **앱 빌드**: Compose/Android 앱 테스트와 실제 레이아웃 검증은 노트북에서 수행한다. 서버에서 앱 테스트를 실행했다고 주장하지 않는다.
