# 말 알아듣기 (coach 계층, voice 담당)

코드: `rest-engine/coach/src/main/kotlin/dev/shimpyo/coach/voice/` 의 `IntentParser.kt`(의도·대답·잠), `OccupantWords.kt`(탑승자 낱말),
`Hangul.kt`(조사), 그리고 `coach/OccupantPhrase.kt`("누가 타나요"의 대답 → 탑승자 목록).
테스트: `src/test/.../voice/IntentParserTest`(테스트 20개, 말 약 580줄: 의도·카드 대답·잠 424줄, 예·아니요 155줄), `voice/HangulTest`, `OccupantPhraseTest`.
실행: `./gradlew -q -p rest-engine :coach:test --tests '*IntentParser*' --tests '*OccupantPhrase*' --tests '*Hangul*'` (서버에서 돈다).

규칙 기반이다(ML 없음). LLM 해석기(`IntentInterpreter`)는 이 규칙이 null을 돌려준 말에만 쓰이고, 에뮬레이터에서는 응답하지 않으므로
(CLAUDE.md) 시연은 이 규칙만으로 돈다. 그래서 규칙은 표로 설명할 수 있어야 하고, 표가 곧 테스트다.

## 1. 공개 API

```kotlin
enum class YesNo { YES, NO, UNKNOWN }
data class CardReply(val answer: YesNo, val other: VoiceIntent?)
sealed interface Spoken {
    data class Intent(val intent: VoiceIntent) : Spoken
    data class Asleep(val occupantId: String?, val asleep: Boolean) : Spoken
}

class IntentParser {
    fun yesNo(text: String?): YesNo
    fun parse(text: String?, occupants: List<Occupant>, activePromptId: String?): VoiceIntent?     // 엔진 의도 하나
    fun replyTo(text: String?, occupants: List<Occupant>, cardStopName: String?): CardReply         // 카드의 음성 질문에 한 대답
    fun parseSpoken(text: String?, occupants: List<Occupant>, activePromptId: String?): Spoken?     // 마이크 버튼: parse + 잠
}
```

| 누가 부르나 | 무엇을 | 왜 |
|---|---|---|
| 카드의 음성 질문이 끝났을 때 (`Msg.AskHeard`) | `replyTo(text, occupants, 카드 정차 이름)` → `Heard(key, answer, other)` | 대답은 하나다. 예전에는 `yesNo`와 `parse`를 따로 불러 "아니 안 급해"가 거절 + 급해 요청이 됐다 (R-F3) |
| 마이크 버튼 (`Msg.Listened`) | `parseSpoken(text, occupants, 떠 있는 카드 key)` | `Intent`는 지금처럼 처리, `Asleep`은 `SetAsleep`과 같은 길로 |
| 그 밖 (기존 호출) | `parse`, `yesNo` | 그대로 동작한다 |

`parse`는 의도 하나만 돌려주므로 카드가 떠 있을 때 대답과 다른 요청이 함께 오면 하나를 고른다: 거절과 함께면 요청이 먼저
("아니 화장실 급해" → 급해), 수락과 함께면 수락이 먼저이되 급해만은 삼키지 않는다("응 화장실 급해" → 급해. 카드에 정차가 있는지
`parse`는 모른다). 카드가 떠 있을 때 마이크로 들은 말도 `replyTo`를 먼저 부르고 `answer`가 UNKNOWN이고 `other`가 null일 때
`parseSpoken(text, occupants, null)`로 넘기면 둘 다 살릴 수 있다(코어의 선택).

## 2. 원칙

1. **띄어쓰기와 문장부호를 지운 글자열에서 찾는다.** STT는 띄어쓰기를 제멋대로 준다("화장실급해", "아니안급해"). 물음표만은
   지우기 전에 본다(4장).
2. **낱말이 있어도 부정했으면 요청이 아니다.** 모든 낱말에: 앞의 '안'("안 급해", "안 가고 싶어"), 뒤의 '-지 않아'·'-진 않아'·
   '-지 말자', '~건 아니야'. "미안 급해"의 '안'은 부정이 아니다(미안·천안·불안·편안·동안).
3. **일·장소의 이름은 뒤에 오는 말로도 꺼진다.** 화장실·산책·식사·점심·기저귀·휴게소·주유소·휴식 같은 이름 뒤의 '~은 괜찮아'·
   '~ 말고'·'~은 됐어'·'~ 필요 없어'·'~ 안 가도 돼/안 해도 돼', 그리고 이미 끝난 일("밥 먹었어", "산책했어", "기저귀 갈았어",
   "화장실 갔다 왔어"). 상태를 말하는 낱말(급해, 졸려, 배고파)에는 쓰지 않는다: "급해, 안 가면 안 돼"는 급하다는 말이고,
   "깜빡 졸았어"·"졸 뻔했어"는 지금 위험하다는 말이고, "점심 안 먹었어"는 배고프다는 말이다.
4. **필요를 말했으면 필요, 묻기만 했으면 되묻기.** 화장실·휴게소라는 낱말만으로는 필요가 아니다. 되묻는 구절("얼마나 더 가야")을
   먼저 떼고 남은 말에서 필요를 찾는다(그 안의 '가야'는 필요가 아니다). 필요와 되묻기가 함께면 필요다("화장실 급한데 얼마나 남았어").
5. **수락은 분명할 때만.** 틀린 수락은 내비에 경유지를 넣고, 틀린 거절은 카드를 닫는다. 틀린 '모름'은 버튼을 기다릴 뿐이다.

| `Accept` / `Decline` | 카드가 떠 있을 때(`activePromptId`)의 대답 (4장) | 카드가 없으면 "응", "아니", "가자"는 뜻이 없다 (→ null) |

누구를 가리켰나(`OccupantNeed.occupantId`, `Asleep.occupantId`): 화면 이름을 그대로 말했으면 그 사람("둘째"), 그다음 첫째·둘째·셋째·막내
(아이 목록의 순서, 막내는 나이), 그다음 유형 낱말(아기 → 영아, 없으면 아이. 아이·애가·딸·아들 → 아이, 없으면 영아. 할머니·어르신,
강아지, 임산부, 와이프·남편·친구 → 운전자 아닌 어른). 가리킨 사람이 설정에 없으면 null이고 엔진이 목적에 맞는 사람을 고른다.
"아이스크림", "아이고", "딸기"는 사람이 아니다. 낱말 목록은 `OccupantWords` 하나를 `OccupantPhrase`와 함께 쓴다.

## 5. 카드 대답은 하나다 (`replyTo`)

`answer`는 4장. `other`는 3장의 '분명히 말한 요청'(낱말만 말한 것은 뺀다) 가운데 아래를 통과한 것이다.

| 대답 | 카드 | 전하는 요청 | 예 |
|---|---|---|---|
| YES | 정차가 있는 카드 | 그 정차에서 풀리지 않는 것만: 그곳이 휴게소가 아닐 때의 식사·수유·주유 | "응 휴게소 들르자", "응 화장실 급해", "응 졸려" → 전하지 않음. 졸음쉼터 카드에 "응 근데 배고파" → `Hungry` |
| YES | 정차 없는 카드 (환기 등) | 쉬자·졸리다는 말만 빼고 전한다 | "응 화장실 급해" → `UrgentRestroom`. "응 쉬자" → 전하지 않음 |
| NO, UNKNOWN | 모두 | 분명한 요청. 단 (a) 휴게소·쉼터라는 낱말로만 알아들은 휴식 요청, (b) '다음·나중'이 붙은 요청(되묻기는 전한다), (c) 카드의 정차 이름을 댄 휴식 요청은 뺀다 | "아니 화장실 급해" → NO + `UrgentRestroom`. "아니 안 급해" → NO뿐. "아니 다음 휴게소에서 쉬자" → NO뿐. "배고파" → UNKNOWN + `Hungry`. "휴게소?", "화장실" → UNKNOWN뿐 |

왜 이렇게 나누나: 수락하면 그 정차에 간다. 화장실·휴식·졸림은 거기서 풀리므로 엔진에 다시 넘기면 "…쉬어 갈까요?"를 한 번 더 묻고
(R-F3), "응 화장실 가자"는 게이지를 NOW로 올리고 간격을 잘못 배운다. 거절한 사람의 '다음 휴게소에서'를 넘기면 엔진이 방금 거절한
곳을 다시 권할 수 있다.

**출발 전 한마디 카드** (`replyTo(…, cardKind = DEPARTURE)`, 2026-11-13 감사): 위 규칙보다 먼저 본다.

| 말 | 대답 | 전하는 요청 |
|---|---|---|
| "이미 다녀왔어", "방금 화장실 다녀왔어요", "아이는 갔다 왔어" | NO | `RestroomDone(누구)`: 화장실 시계를 지금으로 (엔진, 여정 기준점 모두. 배우지 않는다) |
| "다녀올게요"(버튼 이름), "갔다 올게", "다녀와서 출발할게", "화장실 다녀올게", "아이 화장실 보내고 올게" | YES | 없음 (화장실 요청으로 넘기면 가까운 화장실을 다시 묻고 가짜 관측을 남겼다) |
| 그 밖 ("아니 괜찮아", "응") | 위 규칙 그대로 | |

## 6. 잠든 탑승자 (`parseSpoken` → `Spoken.Asleep`)

엔진 의도가 아니다. 코어가 세계마다 '자는 사람' 집합을 들고 `CoachInput.asleepOccupantIds`에 넣는다(연구: 잠든 아이는 간격이 길다).

| 뜻 | 말 |
|---|---|
| 잔다 (`asleep = true`) | 잠들었어, 자고 있어, 자는 중, 곯아떨어졌어, 재웠어, 주무셔, "(아이·애기·첫째·강아지…)(가) 자·자요·잔다·자서", "다 자", "뒤에 다 자", 아직 안 깼어, 아직 자 |
| 깼다 (`asleep = false`) | 깼어, 일어났어, 잠 깼어, 안 자, 안 자고 떠들어, 아직 안 자 |
| 잠 이야기가 아니다 | 졸려·잠 와·잠들 것 같아·자고 싶어(운전자 → `Sleepy`), 한숨 자고 가자(→ `WantRest`), 가자·쉬자, "애들아 가자", "아이 자리", "아이가 자고 싶대" |

`occupantId`: 가리킨 사람. 가리키지 않았으면 한 명뿐인 아이(아이·영아). 아이가 여럿이거나("애들 다 자" 포함) 설정에 아이가 없으면
null: 코어가 고른다. 설정에 없는 어른·반려견 이야기("와이프 자고 있어")는 `Asleep`으로 내지 않는다(아이에게 붙지 않게).
요청이 함께 있으면 요청이 먼저다("아이가 깼는데 화장실 가고 싶대" → 화장실). 잠 이야기에 섞인 '피곤·졸려'는 그 사람 이야기라 잠이
먼저다("피곤했는지 잠들었어"). "나도 졸려"처럼 자신을 가리키면 운전자의 졸림이다.

## 7. 일부러 알아듣지 않는 것

## 8. 한계

- STT가 물음표를 주지 않으면 "네?"(못 들었다)와 "네"를 가를 수 없다. 수락으로 듣는다.
- "아니"는 말머리 감탄사("아니 왜 이렇게 막혀")여도 거절이다. 카드가 닫힌다.
- "급해"는 화장실로 읽는다. "시간이 급해", "급하게", "급한 일"만 뺀다.
- 사람 이름은 모른다("지안이가 화장실 가고 싶대" → 누구인지 null). 화면 이름(`Occupant.label`)으로 넣어 두면 알아듣는다.
- 한 말에 대답과 요청이 둘 다 있을 때 `parse`(의도 하나)는 하나를 버린다. 카드 대답은 `replyTo`로 받을 것.
- 조사: `Hangul.eulReul`·`iGa`·`eunNeun`·`euRo`. 마지막 한글 음절의 받침으로 정한다("옥산휴게소(부산방향)은", "화장실로").
  규칙은 여기 한 곳이다(`GoToPlanner`의 은/는 사본을 지웠다).
