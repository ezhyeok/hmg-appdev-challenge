# 쉼표 화면 설계

작성 2026-11-11. 토큰 값과 출처는 `docs/design/pleos-design-tokens.md`(이하 "토큰 문서"), 기능과 판단 로직은 `docs/product/SPEC.md`, 엔진 데이터 형태는 `rest-engine/src/main/kotlin/dev/shimpyo/engine/Api.kt`를 따른다. 테마 코드는 `app/src/main/java/dev/shimpyo/app/ui/theme/`에 있다.

## 읽는 법

- 와이어프레임 축척: 가로 1칸 = 20dp, 세로 1줄 ≈ 40dp. 기본 그림은 **세로 윈도 840×1184dp**(Connect-S 17" 1:1 분할, 에뮬레이터 기본)로 42칸이고, 가로 윈도 1700×1184dp는 85칸이다. 글자 길이는 축척이 아니다.
- 기호: `+====+` Filled 버튼(주 행동), `+----+` Basic 버튼 또는 카드, `[ ]` 칩·배지·아이콘 자리, `[ o ]`/`[   ]` 스위치 켜짐/꺼짐, `v` 드롭다운, `>` 다음 화면, `[<]` 뒤로.
- 토큰 표기: 색은 `colors.X`(= `ShimpyoTheme.colors.X`), 글자는 `PleosType.X`·`DriveType.X`·`PleosButtonType.X`, 크기는 `Dimens.X`.
- [제안]은 가이드에 근거가 없어 이 문서가 정한 것이다.

## 0. 공통

### 0.1 화면 구조와 주행 상태

| 화면 | 주행 중 | 정차 중 |
|---|---|---|
| 1. 주행 (홈) | 주행 변형 | 정차 변형 |
| 2. 계획 | 들어갈 수 없음 | O |
| 3. 급해 결과 | 주행 변형(1~2곳) | 정차 변형(목록) |
| 4. 탑승자 설정 (+상세) | 들어갈 수 없음 (NO_SETUP) | O |
| 5. 휴식 기록 | 들어갈 수 없음 (LIMIT_CONTENT) | O |
| 6. 설정, 시연 패널 | 들어갈 수 없음 (NO_SETUP) | O |

- **주행 판정**은 `CarUxRestrictions.isRequiresDistractionOptimization()`로 한다(`CarUxRestrictionsManager` 리스너). 지역별 제한은 플랫폼이 내려 주므로 기어·차속으로 직접 판단하지 않는다(토큰 문서 7.1). 엔진의 `CoachOutput.parked`(기어 P)는 휴식 표시에만 쓴다.
- 주행 제한이 켜질 때 2·4·5·6번 화면에 있었다면 주행 화면으로 돌아가고 토스트 "주행 중에는 주행 화면만 보여요"를 띄운다. 입력하던 값은 저장해 두었다가 정차 후 그 화면으로 돌아가면 복원한다(심사 기준: 상태 복원).
- **헤더**는 Pleos Page Navigation이다. 정차 중 `[앱 아이콘 80] [주요 메뉴 v] … [suffix 아이콘 버튼]`, 높이 160(40+80+40). 주요 메뉴 드롭다운 항목은 주행·계획·탑승자·기록·설정 5개(1 depth). 주행 중에는 드롭다운을 끄고(제목만, 화살표 없음) suffix는 마이크만 두며, 위아래 여백을 16으로 줄여 높이 112로 쓴다 [제안, `Dimens.Drive.headerHeight`].
- **뒤로**: 급해 결과, 탑승자 상세, 시연 패널은 이전 화면으로. 최상위 화면에서는 CCP Back이나 뒤로 동작에 `moveTaskToBack(true)`로 앱을 숨긴다(종료 금지, CCP 가이드 필수 항목).
- **윈도**: manifest에 `screenOrientation`이 없어 기본은 세로 윈도다. 폭 1000dp 이상이면 2단(가로), 높이 1000dp 미만이면 compact(`Dimens.Window`). 가로는 정보만 더하고 버튼 구성은 세로와 같게 둔다(심사 기준: 기능 패리티).
- **텍스트 입력 없음**: 이 앱은 키보드를 쓰지 않는다. 이름은 프리셋("첫째", "둘째"), 숫자는 스테퍼로 받는다(가이드: 키보드보다 프리셋·음성 우선).

### 0.3 비주얼 아이덴티티 [제안]

**원칙.** 바탕은 시스템과 같은 무채색이고, 색은 상태가 바뀔 때만 쓴다. 앱 고유의 강조색은 만들지 않는다. 브랜드 테마(42dot·Kia·Genesis)가 시스템 색을 바꾸므로 앱은 공통 토큰만 써야 기본 UI와 어울린다. 앱의 개성은 연료 게이지처럼 생긴 "사람 게이지"(큰 숫자 + 막대)로 낸다.

**게이지 단계와 색** (엔진 `Level`, 경계는 SPEC 4.1·4.2)

| 단계 | 화장실 남은 시간 | 막대 색 | 배지 | 단계 문구 | 음성 |
|---|---|---|---|---|---|
| OK | 45분 초과 | `gaugeOk` (informative_positive) | 없음 | 여유 | 말하지 않음 |
| WATCH | 45~20분 | `gaugeWatch` (= OK 색) | 없음 | 확인 | 묻지 않음. 추천 카드만 갱신 |
| SOON | 20~10분 | `gaugeSoon` (regulation_orange) | [곧] | 곧 | 다음 기회 진입로 2~5km 전에 한 번 묻는다 |
| NOW | 10분 미만 | `gaugeNow` (informative_negative) | [지금] | 지금 | 가장 가까운 곳을 바로 제안 |

- 색은 행동이 필요해지는 SOON부터 바뀐다. OK와 WATCH를 다른 색으로 나누면 운전자가 볼 때마다 의미를 해석해야 한다.
- 라이트 테마에서 주황·빨강 막대는 대비 4.5:1이 안 된다(토큰 문서 1.8). 그래서 단계는 색 + 배지(어두운 글자, 5.2:1 이상) + 숫자(text_primary)로 같이 보여 준다.
- 빨강은 NOW 게이지, 급해 버튼, 정체 구간에만. 주황은 SOON, 화장실 공백에만. 초록(informative_active)은 스위치 켜짐 전용으로 남기고(시스템 의미), 보라(자율주행)와 Gleo 색은 쓰지 않는다.
- 질문 중에는 추천 카드 테두리를 그 게이지 단계 색 4dp로 바꾼다(평소 2dp `cardStroke`).

**아이콘.** Material Symbols(Apache 2.0) Outlined를 48dp VectorDrawable로 가져와 쓴다(새 의존성 없음, 라이선스는 설정 > 정보에 표기). 가이드의 48dp 그리드, Filled/Outlined 규칙과 맞는다. 선택된 상태와 급해 버튼만 Filled. 아이콘 옆에는 항상 글자 라벨을 둔다(가이드). 이름은 Material Symbols 목록에서 확인하고 가져온다.

| 화장실, 화장실 게이지 | `wc` | 급해 버튼은 Filled |

### 0.4 음성 우선

- 질문은 한 번에 하나, 대답은 "응/아니"(SPEC 3장 8번). 엔진의 `Prompt.speech`를 TTS로 읽고, 화면은 같은 내용을 확인용으로 보여 준다.
- 묻지 않는 때: 다음 회전 500m 이내, 최근 10초 안에 제동이나 큰 조향(SPEC 4.6).
- TTS 앞에 150~200ms 묵음, 오디오 포커스는 `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`, Gleo가 불리면(`AUDIOFOCUS_LOSS_TRANSIENT`) 바로 멈춘다(토큰 문서 7.6).
- 마이크 버튼으로 듣기를 시작·중지할 수 있다(가이드: 대화의 시작·종료·중단은 수동으로도 가능). 상태 문구는 "듣는 중"과 "말하는 중"을 나눈다. 주행 중에는 맥박처럼 움직이는 애니메이션 대신 고정된 링을 쓴다.
- 질문 뒤 8초 동안 대답을 듣는다 [제안]. 대답이 없으면 결정하지 않은 것으로 두고, 단계가 오르면 다시 묻는다(SPEC 4.6).
- 엔진 `VoiceIntent`와 화면 동작: "화장실 급해"(UrgentRestroom) → 3번 화면, "응/아니"(Accept/Decline) → 1번 화면의 들르기/괜찮아요, "좀 쉬고 싶어"·"졸려"(WantRest·Sleepy) → 쉬어 갈 곳 제안, "화장실까지 얼마나 남았어?"(HowLong) → 게이지를 읽어 줌, "아이가 화장실 가고 싶대"(OccupantNeed) → 다음 기회 또는 급해.
- 질환 이름은 소리 내어 말하지 않는다. 다른 탑승자가 듣는다. 이유는 "민감 탑승자 기준 45분"처럼 말한다.

## 1. 주행 화면

### 1.1 목적

운전 중 1~2초 보고 "지금 괜찮은지, 다음에 어디서 쉬는지"를 알게 한다. 결정이 필요하면 한 번에 하나만 묻고(들르기/괜찮아요), 급할 때는 한 번에 급해 결과로 간다. 질문과 대답은 음성이 먼저고 화면은 확인용이다.

### 1.2 데이터

| 화면 요소 | 엔진 출력 |
|---|---|
| 화장실 게이지 | `CoachOutput.restroom: Gauge(minutes, level, reasons, drivenBy)` |
| 피로 게이지 | `CoachOutput.fatigue` |
| 추천 카드 | `CoachOutput.next: Recommendation(stop, purposes, reasons)`, 장소는 `StopCandidate(name, kind, routeDistanceM, etaS, detourS, directionOk)` |
| 질문 | `CoachOutput.prompt: Prompt(kind, speech, stop, expiresAt)` |
| 정차 여부 | `CoachOutput.parked` |


- 왼쪽 단(760): 게이지 2장 + "앞으로 경로" 띠(보기 전용, 포커스 없음). 다음 약 120km의 화장실 기회(o), 화장실 공백(:), 정체(~), 추천 정차(O)를 거리 비례로 그린다.
- 오른쪽 단(804): 추천 카드, 행동 줄, 급해 버튼. 버튼은 세로와 같다.

**compact (윈도 높이 1000 미만: 14.6", 12.9", W, WF)**

헤더 112, 구역 간격 16, 게이지 카드 176(숫자 `DriveType.GaugeValueCompact` 48), 추천 카드 200 이상, 급해 버튼 100, 아래 16. 세로 합 768이라 가장 낮은 WF 세로(648×800)에도 들어간다. 폭이 좁은 12.9" 세로(628)에서는 좌우 여백을 24로 줄여 게이지 두 장(각 282 이상, 최소 `Dimens.Gauge.minWidth` 260)을 나란히 둔다.

### 1.4 게이지 카드

| 요소 | 내용 | 토큰 |
|---|---|---|
| 이름 | 아이콘 48 + "화장실" / "피로" | `DriveType.GaugeLabel` (28), `colors.textSecondary`, 아이콘 `colors.iconSecondary` |
| 숫자 | 남은 분. 120 이상이면 "2시간+" | `DriveType.GaugeValue` (60, 고정폭 숫자), `colors.textPrimary` |
| 단위 | "분" | `DriveType.GaugeUnit` (32), `colors.textSecondary` |
| 배지 | SOON [곧], NOW [지금], 오른쪽 위 | 0.2 단계 배지 |
| 막대 | 채움 = 남은 분 ÷ 그 탑승자의 기준 간격(화장실) 또는 120분(피로) | 높이 `Dimens.Gauge.barHeight` 24, 반경 12, 빈 곳 `colors.gaugeTrack`, 채움 `colors.gaugeOk/Watch/Soon/Now` |
| 경계 눈금 | SOON 경계(화장실 20분, 피로 연속 100분)에 세로선 | 4×40, `colors.textTertiary` |
| 이유 한 줄 | `Gauge.reasons` 첫 번째(12자 이하). 예 "아이 기준", "연속 1:48", "환기 권장" | `DriveType.Minimum` (28), `colors.textSecondary` |

- 막대 길이와 색은 단계가 바뀔 때 한 번만 전환한다(`DURATION_MEDIUM_1` 250ms). 매초 갱신되는 분 숫자는 애니메이션 없이 바꾼다.
- 게이지는 누를 수 없고 포커스도 받지 않는다.

### 1.5 추천 카드와 질문

| 줄 | 내용 | 토큰 |
|---|---|---|
| 맥락 | 질문 종류: LAST_CHANCE "정체 전 마지막 화장실", REST_SUGGESTION "쉬어 갈 곳", 질문 없음 "다음 화장실" | `PleosType.BodyMediumStrong`, `colors.textSecondary` |
| 이름 | 장소 이름 한 줄, 넘치면 말줄임 | `DriveType.StopName` (40), `colors.textPrimary` |
| 거리·시간 | "4.2km · 3분 · 경로 위"(우회면 "+4분 우회", 방향을 모르면 생략) | `DriveType.StopMeta` (30), `colors.textSecondary` |
| 이유 칩 | `Recommendation.reasons` 앞 2개. 예 "정체 40분 전 마지막", "아이 동승", "2시간 연속 주행", "운전 패턴 변화" | 0.2 이유 칩 |

- **질문 중**: 카드 테두리 4dp 단계 색, 행동 줄에 [들르기](Filled Large) [괜찮아요](Basic Large)가 나타난다. 화면 글자는 TTS 문장과 같은 내용을 줄여 보여 준다.
- **들르기**(또는 "응"): `NaviKit.addWaypoint` → 카드 맥락이 "경유지로 넣었어요", 버튼은 사라지고 TTS "안성휴게소를 경유지로 넣었어요". 실패하면 버튼은 그대로 두고 토스트 "경유지를 넣지 못했어요. 내비에서 확인해 주세요".
- **괜찮아요**(또는 "아니"): 버튼이 사라지고, 같은 종류 질문은 15분 또는 다음 기회까지 쉰다(SPEC 4.6).
- `Prompt.expiresAt`이 지나거나 진입로를 지나면 질문을 거둔다.

### 1.6 정차 변형

```
+----------------------------------------+
|  [앱] 주행 v                    [...]  |
|                                        |
|  +---------------+  +---------------+  |
|  | 화장실        |  | 피로          |  |
|  | 95분          |  | 휴식 7분째    |  |
|  | ===========.. |  | ====......... |  |
|  | 방금 들름     |  | 10분이면 회복 |  |
|  +---------------+  +---------------+  |
|                                        |
|  +----------------------------------+  |
|  | 다음 계획                        |  |
|  | 옥산휴게소 / 66km / 14:05        |  |
|  | [화장실] [휴식]                  |  |
|  +----------------------------------+  |
|                                        |
|  +===============+  +---------------+  |
|  |   계획 보기   |  |    탑승자     |  |
|  +===============+  +---------------+  |
|                                        |
|  +==================================+  |
```

- 헤더에 주요 메뉴 드롭다운과 더보기(설정, 시연 패널)가 돌아온다(높이 160, 그림은 축약).
- 기어 P 중이면 피로 게이지에 "휴식 7분째", 이유 줄에 "10분이면 회복"(SPEC 4.2: 휴식 판정 P 10분 이상). 화장실 정차로 판정되면(P 3분 + 문 열림) 화장실 게이지가 차오르고 "방금 들름".
- 추천 카드는 계획이 있으면 "다음 계획"(첫 정차와 목적 칩), 없으면 "다음 화장실".
- 행동 줄: [계획 보기](Filled) [탑승자](Basic). 급해 버튼은 그대로.

### 1.7 인터랙션

| 입력 | 동작 |
|---|---|
| 터치 | 들르기, 괜찮아요, 급해, 마이크. 게이지·카드·칩은 누를 수 없다(주행 중 depth를 늘리지 않는다) |
| CCP | 회전 순서: 마이크 → 들르기 → 괜찮아요 → 급해. 기본 포커스는 질문 중이면 들르기, 아니면 급해. 누르기 = 실행, Back = 앱 숨김 |
| 음성 | 질문 → "응/아니". "화장실 급해", "화장실까지 얼마나 남았어?", "좀 쉬고 싶어" 언제든 |
| 앱이 안 보일 때 | 포그라운드 서비스가 음성으로 묻는다. 필요하면 시스템 알림(App icon 타입, 버튼 [들르기][괜찮아요])을 쓴다. 운전과 관련된 알림만 낸다(가이드) |

### 1.8 빈 상태와 오류

| 상황 | 표시 |
|---|---|
| 게이지 계산 전(`minutes == null`) | 숫자 "--", 이유 줄 "계산 중", 막대 비움. 로딩 애니메이션 없음 |
| 길안내 없음(`RouteState.guiding == false`) | 맥락 "진행 방향 가까운 화장실", 앱이 진행 방향으로 추린 후보 중 첫 번째 |
| 앞쪽에 후보 없음 | 카드 "앞쪽 20km 안에 화장실 정보가 없어요". 급해 버튼은 그대로 |
| 위치 없음 | 카드 "위치를 확인하는 중이에요". 게이지는 시간 기반이라 계속 보인다 |
| 음성 꺼짐 | 마이크 아이콘에 사선, 질문은 화면에만 |
| 경로 거리 조회 실패 | 직선거리 추정값에 "약"을 붙인다("약 4km") |

## 2. 계획 화면 (정차 중)

### 2.1 목적

출발 전이나 정차 중에 경로 앞의 화장실 기회, 화장실 공백(정체·터널·드문 구간), 정체 구간, 계획된 정차를 한 번에 본다. 화장실·2시간 휴식·식사·주유·수유를 묶은 피트스톱 계획(SPEC 4.5)을 경유지로 넣는다.

데이터: `PitStopPlan(stops: List<PlannedStop(stop, purposes, dwellMin, arriveInS)>, totalStopMin, notes)`, `RouteState(remainDistanceM, remainTimeS, congestion)`, 경로 앞 `StopCandidate` 목록.

### 2.2 배치

**세로 윈도**

```

|                                        |

|  | 정차 2번 / 쉬는 시간 30분        |  |
|  | +==============================+ |  |
|  | |    계획대로 경유지 넣기      | |  |
|  | +==============================+ |  |
|  +----------------------------------+  |
|                                        |
|   @   지금           0km   12:05       |
|   |                                    |
|   o   기흥휴게소    18km   12:20       |
|   |                                    |
|  (1)  안성휴게소    52km   12:45       |
|   |   [화장실] [식사] [주유]  20분     |
|   :   화장실 공백 58분 (터널 3개)      |
|   ~   정체 40분 (안성-천안)            |
```

|---|---|---|---|
| @ | 지금 위치 | 64 | 아이콘 `colors.iconPrimary` |
| o | 화장실 기회(휴게소, 화장실 있는 졸음쉼터) | 100 | 표식 24 링 `colors.timelineOpportunity`, 이름 `PleosType.TitleSmall`, 거리·시각 `PleosType.BodyMedium` 고정폭 숫자 `colors.textSecondary` |

| : | 화장실 공백 | 64 | 레일 구간 `colors.timelineGap`, 글자 `PleosType.BodyMediumStrong` `colors.textPrimary` "화장실 공백 58분 (터널 3개)" |
| ~ | 정체 | 64 | 레일 구간 `colors.timelineCongestion`, "정체 40분 (안성-천안)" |
| (회색) | 터널 | 레일 표시만 | `colors.timelineTunnel`, 공백 줄의 설명에 포함 |
| # | 목적지 | 64 | |

| 입력 | 동작 |
|---|---|
| 터치 | 정차 줄 → 상세. 목적 토글 → 계획 다시 계산. [계획대로 경유지 넣기] → 정차를 순서대로 `addWaypoint`. 내비 요청은 응답을 기다리며 하나씩 보낸다(내비 요청 사이 간격 규칙, CLAUDE.md). 2초를 넘을 수 있으므로 버튼 안에 "1/2 넣는 중"을 표시한다(심사 기준 2초) |
| 스크롤 | 정차 중이라 허용. 끝에서 바운스(가이드) |
| CCP | 회전: 새로 계산 → 경유지 넣기 → 목록 항목 순서. 누르기 = 상세. 목록은 포커스를 따라 스크롤 |
| 음성 | "계획 세워줘", "식사도 넣어줘", "경유지로 넣어줘" |
| 주행 시작 | 1번 화면으로 돌아간다. 계획의 첫 정차가 추천 카드로 이어진다 |

### 2.4 빈 상태와 오류

| 상황 | 표시 |
|---|---|
| 목적지 없음 | "내비에서 목적지를 정하면 계획을 세울 수 있어요". NaviHelper에 POI 검색이 없으므로 앱에서 목적지를 받지 않는다 |
| 계산 중 | Loading 애니메이션(Tension, 가이드) + "계획을 세우는 중" |
| 경로 정보 실패 | "경로 정보를 받지 못했어요" + [다시 시도] |
| 정차가 필요 없음 | "도착까지 쉬지 않아도 돼요 (남은 45분)" |
| 화장실 기회 정보 없음 | "이 경로에는 화장실 기회 정보가 없어요" |
| 경유지 일부 실패 | 팝업 "2곳 중 1곳만 넣었어요" [다시 시도](Filled) [닫기](Basic) |

## 3. 급해 결과

### 3.1 목적

"화장실 급해" 한마디나 급해 버튼 한 번으로, 지금 차를 세울 수 있고 열려 있으며 진행 방향에 있는 화장실을 고른다. 순위는 엔진이 정한다(SPEC 4.4: 총 소요 = 주행 + 주차·도보 + 유턴 벌점, 영업 종료 제외, 야간 비상벨·CCTV 가점, 영아 동승 시 교환대 가점).

데이터: `CoachOutput.urgent: List<RankedStop(stop, totalTimeS, why)>`, `StopCandidate.facilities/parkable/openNow/directionOk`.

### 3.2 주행 변형

```
+----------------------------------------+
|  [<] 급해                     [마이크] |
|                                        |
|  +==================================+  |
|  | 1  주유소 화장실 (OO주유소)      |  |
|  |    3분 / 1.1km / 진행 방향       |  |
|  |    [24시간] [주차 가능]          |  |
|  |                       여기로  >  |  |
|  +==================================+  |
|                                        |
|  +----------------------------------+  |
|  | 2  공영주차장 화장실             |  |
|  |    5분 / 1.9km / 진행 방향       |  |
|  |    [비상벨] [CCTV]               |  |
|  |                       여기로  >  |  |
|  +----------------------------------+  |
|                                        |
|                                        |
|                                        |
|  +----------------------------------+  |
|  |              닫기                |  |
|  +----------------------------------+  |
|                                        |
+----------------------------------------+
```

- 결과는 최대 2곳(`DriveLimits.MAX_URGENT_RESULTS`). 카드 전체가 하나의 터치 영역이다(높이 `Dimens.Drive.urgentResultCardMinHeight` 220 이상).
- 1순위 카드는 Filled(`colors.buttonFilledEnabled` 바탕, `colors.textOnFilledPrimary` 글자), 2순위는 Basic(`colors.buttonBasicEnabled`).
- 줄: 순위와 종류 아이콘 48, 이름 `DriveType.StopName`, "3분 · 1.1km · 진행 방향" `DriveType.StopMeta`, 배지 최대 2개(상황에 맞는 것: 영아 동승이면 교환대, 22~06시면 비상벨·CCTV, 그 외 24시간·주차 가능), 오른쪽 아래 "여기로 >" `DriveType.ActionLabel`.
- [닫기] Basic Large. 결과가 1곳이면 2순위 자리는 비워 둔다.
- 음성: "가장 빠른 곳은 OO주유소 화장실, 3분이에요. 안내할까요?" → "응"이면 경유지로 넣고(목적지는 유지, 길안내가 없으면 `requestRoute`) 1번 화면으로 돌아간다. "다음"이면 2순위를 읽는다.
- 화면은 자동으로 넘어가거나 회전하지 않는다. 지도는 그리지 않는다(지도는 내비 앱이 보여 준다).

```
+----------------------------------------+
```

- 목록 항목: 순위, 이름, 총 소요 시간, 거리·방향·영업시간, 시설 줄(교환대·비상벨·CCTV를 아이콘 Filled = 있음, Outlined + 사선 = 없음, 글자 함께. 그림의 o/x), 주차 형태(주차장·갓길·불가). 높이 140(세 줄), `PleosType.TitleSmall` / `BodyMedium` / `LabelMedium`.

| 주행 상태 전환 | 정차 변형에서 출발하면 목록 앞 2개만 남긴 주행 변형으로 바뀐다(필터 줄 숨김) |

| 상황 | 표시 |
|---|---|

| 경유지 실패 | 토스트, 결과는 그대로 |

## 4. 탑승자 설정 (정차 중)

### 4.1 목적

누가 탔는지에 따라 화장실 기준 시간과 필요한 시설이 바뀐다(SPEC 3장 4번, 4.1 표). 주행 중에는 차량 설정과 같은 NO_SETUP 대상이라 화면에 들어갈 수 없다.

데이터: `TripProfile(occupants: List<Occupant(id, type, ageYears, label)>, driverSleepHours, lastRestroomAt)`, 유형별 기본 간격은 `CoachConfig.prior*Min`.

### 4.2 배치

**목록 (세로 윈도)**

```
+----------------------------------------+
|  [앱] 탑승자 v                  [...]  |
|                                        |
|  +----------------------------------+  |
|  | [운전] 운전자 (성인)      180분 >|  |
|  +----------------------------------+  |
|  | [아이] 아이 5세            90분 >|  |
|  +----------------------------------+  |
|  | [반려] 반려견             180분 >|  |
|  +----------------------------------+  |
|                                        |
|  +----------------------------------+  |
|  |         + 탑승자 추가            |  |
|  +----------------------------------+  |
|                                        |
|  지금 기준: 90분마다 화장실            |
|  가장 엄격한 탑승자를 따릅니다         |
|  건강 정보는 이 차 안에만 저장됩니다   |
|                                        |
+----------------------------------------+
```

- 탑승자 카드: 유형 아이콘 48, 이름(`label`, 비면 유형 이름), 기준 간격, `>`. 높이 100, 카드 묶음(목록 컨테이너 반경 32, 항목 사이 구분선).
- 운전자 카드는 항상 있고 지울 수 없다.
- [+ 탑승자 추가](Basic Large) → 유형 선택: 8개 유형(성인, 아이, 영아, 임신부, 어르신, 과민성 방광, 과민성장증후군, 반려견)을 2열 격자의 Basic Medium 버튼(80, 아이콘 + 글자)으로.
- 아래 요약: 지금 게이지를 정하는 탑승자와 그 기준(`Gauge.drivenBy`). "건강 정보는 이 차 안에만 저장됩니다"(`PleosType.BodyMedium`, `colors.textTertiary`).

**상세**

```
+----------------------------------------+
|  [<] 아이                       [삭제] |
|                                        |
|  나이                                  |
|  +----------------------------------+  |
|  |  [ - ]        5세         [ + ]  |  |
|  +----------------------------------+  |
|                                        |
|  화장실 간격 기준                      |
|  +----------------------------------+  |
|  |  [ - ]       90분         [ + ]  |  |
|  +----------------------------------+  |
|  기본값 90분 (3-6세)                   |
|                                        |
|  필요한 시설                           |
|  기저귀 교환대                  [ o ]  |
|  수유실                         [   ]  |
|                                        |

```

| 항목 | 컨트롤 | 엔진 |
|---|---|---|
| 이름 | 프리셋 드롭다운(첫째, 둘째, 셋째, 할머니, 할아버지…). 키보드 없음 | `Occupant.label` |
| 나이(아이) | 스테퍼 3~12세 | `Occupant.ageYears` |
| 화장실 간격 기준 | 스테퍼 30~240분, 10분 단위. 아래에 기본값 | 엔진에 필드 없음 → `Occupant`에 `intervalOverrideMin: Int? = null` 추가 필요 |
| 출발 전 마지막 화장실 | 토글 버튼 4개: 방금 / 30분 전 / 1시간 전 / 모름 | `TripProfile.lastRestroomAt` |
| 지난밤 수면(운전자) | 토글 버튼 3개: 6시간 미만 / 6시간 이상 / 모름 | `TripProfile.driverSleepHours` |
| 필요한 시설 | 스위치: 기저귀 교환대, 수유실, 반려동물 구역 (유형에 따라 기본 켜짐) | 엔진에 필드 없음 → 탑승자별 필요 시설 추가 필요(지금은 유형으로 추정) |

|---|---|---|
| 휴식 간격(피로 NOW) | 스테퍼 90~150분, 기본 120 | `CoachConfig.fatigueNowMin` (SOON·WATCH는 같은 차이로 따라 움직인다) |
| 정체 알림 | 토글 버튼: 20분 / 30분 / 40분 이상 | `CoachConfig.congestionAlertMin` |

가로 윈도: 왼쪽 탑승자 목록 428 + 오른쪽 상세. 상세는 바로 고쳐지고 [저장]은 오른쪽 아래.

### 4.3 인터랙션

| 입력 | 동작 |

## 5. 휴식 기록 (정차 중)

### 5.1 목적

기어 P와 문 열림으로 자동 기록한 정차(SPEC 3장 5번)를 보여 주고, 내 휴식 습관과 앱이 배운 것을 짧게 알려 준다. 기록을 고치면(화장실 정차였는지) 개인 모델이 갱신된다(`PersonalMemory.restroomIntervalsMin`).

### 5.2 배치

```
+----------------------------------------+
|  [앱] 기록 v                    [...]  |
|                                        |
|  +---------------+  +---------------+  |
|  | 평균 휴식간격 |  | 제안 수락     |  |
|  | 1시간 52분    |  | 4번 중 3번    |  |
|  | 지난주 2:10   |  | 마지막 기회   |  |
|  +---------------+  +---------------+  |
|                                        |
|  연속 주행 시간 (최근 8번)             |
|  120분 - - - - - - - - - - - - - - -   |
|         ##                             |
|     ##  ##      ##          ##         |
|  ## ##  ##  ##  ##  ##  ##  ##         |
|                                        |
|  오늘                                  |
|  12:45  안성휴게소   22분  [화장실]    |
|  10:58  기흥휴게소    9분  [휴식]      |
|  어제                                  |
|  18:20  이름 없는 정차 4분  [확인?]    |
|                                        |
+----------------------------------------+
```

- 인사이트 카드 최대 3장(가로 윈도), 세로는 2장: 평균 휴식 간격(이번 주, 지난주 비교), 질문 수락(`PersonalMemory.promptStats`), 배운 것("화장실 간격이 기본값보다 길어서 게이지를 늘렸어요"). 숫자 `PleosType.TitleMedium`, 설명 `PleosType.BodyMedium`.
- 막대그래프: 최근 8번의 연속 주행 시간. 120분 점선(`colors.textTertiary`), 막대 색은 그 구간이 끝날 때의 피로 단계 색(`colors.gauge*`). 정적 그림, 숫자 라벨 `PleosType.LabelMedium`(정차 화면이라 허용).
- 목록: 날짜별. 시각, 장소(가까운 후보 이름, 없으면 "이름 없는 정차"), 머문 시간, 종류 칩(화장실·휴식·식사). 판정이 애매한 정차는 [확인?] 칩 → "화장실 정차였나요?" [예](Filled) [아니요](Basic).
- 가로 윈도: 왼쪽 목록 428 + 오른쪽 인사이트와 그래프.

### 5.3 인터랙션과 빈 상태

| 입력·상황 | 동작·표시 |
|---|---|
| CCP | 인사이트 카드는 포커스 없음. 목록 항목 순서, 누르기 = 종류 확인 |
| 음성 | "오늘 몇 번 쉬었어?" → 읽어 줌 [제안] |
| 기록 없음 | "아직 기록이 없어요. 차를 세우고(P) 문을 열면 자동으로 기록돼요" |
| 불러오기 실패 | "기록을 불러오지 못했어요" + [다시 시도] |
| 인사이트에 필요한 기록 부족(3번 미만) | 인사이트 카드 대신 "3번 더 쉬면 습관을 알려 드릴게요" |

- 가로 윈도: 왼쪽 구역 목록(음성, 차량, 데이터, 정보) 428 + 오른쪽 항목. 가이드의 Theme 설정 화면 도식과 같은 2단 구성이다.


- 2차 PT용. 설정 > 버전 7번 탭으로 켠다. 주행 중에는 들어갈 수 없다.
- 시나리오 4개(SPEC 7장): 귀성길 정체, 오후 졸음, 도심 급해, 휴식 기록. 누르면 시연 모드로 정체·위치·시각을 주입한다. 차량 상태(기어, 차속, 도어)는 Virtual Console(`tools/vc/vc.sh`)로 바꾼다.
- 주입값 스테퍼: 정체 길이, 시각, 운전 편차 점수.
- 상태 줄: VC 시뮬레이터 세션, 기어, 차속, `CarUxRestrictions` 상태. 시연 중 화면이 왜 바뀌는지 설명할 때 쓴다.
- [전부 초기화](Basic Large) → 팝업 확인.

## 7. 주행 화면 검증 목록

에뮬레이터 + Virtual Console에서 확인할 것.

- [ ] 기어 D + 40km/h에서 `requiresDistractionOptimization`이 켜지면 2·4·5·6번 화면에서 1번으로 돌아온다. P로 돌리면 메뉴가 다시 열린다.
